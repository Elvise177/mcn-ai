# 分发指南（macOS）

> **2026-08-19 起：正式签名 + 公证已接上，本文只留背景。**
> 操作手册（一次性准备 / 每次发版怎么走 / 更新源怎么切）看 **`docs/RELEASE.md` 的「发版手册」**，
> 别照着本文旧版本的步骤敲——那一版是按「App 专用密码」写的，现在走的是 App Store Connect API Key。

## 现在是什么形态

`electron-builder.yml` 里：

- `hardenedRuntime: true` + `entitlements: build/entitlements.mac.plist`（三条，每条都写了理由）
- `notarize: true` + 三个 `APPLE_API_*` 环境变量 → notarytool 公证 → 自动 staple 订票
- `publish: generic` → 出 `latest-mac.yml`，供 electron-updater 自动更新

客户拿到 dmg 之后**双击就能开**：不需要右键打开，不需要 `xattr -rd com.apple.quarantine`。
dmg 里那份「安装说明.txt」已经撤掉了（那是未签名时代的绕行说明，留着反而让客户以为要做额外操作）。

## 以前是什么形态（存档，别再用）

未签名（`identity: null`）时，别人通过微信/网盘/浏览器收到 dmg，macOS 会打上
`com.apple.quarantine`，Apple Silicon 对「未签名 + 隔离标记」直接报**"已损坏，无法打开"**
（不是文件真坏了，右键打开也无效）。当时的绕行是让用户跑一次
`sudo xattr -rd com.apple.quarantine /Applications/mcn-ai.app`。

**这条绕行现在不需要了**，但它解释了为什么老客户机上那份 app 是"手动放行过"的——
换成签名版是覆盖安装，Gatekeeper 侧不用再做任何事。

## 两条仍然成立的注意

- 公证要连 Apple 服务器，国内网络偶尔断在上传那一步，挂代理跑 `npm run dist`
- **签名后 asar 内容不能再手改**，改了必须重新打包重新公证（改完不重签 = 签名失效 = 客户机打不开）
