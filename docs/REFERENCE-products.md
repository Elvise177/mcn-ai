# 参照产品对照（REFERENCE-products）

> 2026-09-02 ｜ 参照物：**Claude Desktop 1.40609.1**（Anthropic）与 **WorkBuddy AI 5.4.3**（腾讯），本机均已安装登录。
> 采集方式：只读——读两个应用包内的字符串表与资源清单（Claude 的 `en-US.json` 605 条串；WorkBuddy 的 `menu-i18n.js`/`marketplace.json`/`curated-experts.json`/`package.json`）+ 官方文档与评测；**未改两个产品的任何设置或数据目录**。原始清单（含每条的证据 key / 路径 / URL 与确定度）见会话 scratchpad `audit/B-products-raw.md`。
> 与 SamePage 的对照基线：`PRODUCT-AUDIT.md` 卷二 + `desktop/docs/对标清单.md`。
> 记号：**它有我无** / **我有它无** / **都有·差距**。「它有我无」每条标：对 MCN 客户价值 **高/中/低**、实现成本 **大/中/小**、建议（做 / 不做+理由 / 团队版再做）。

## 0. 三个产品一句话定位

| 产品 | 定位 | 底座 |
|---|---|---|
| Claude Desktop | claude.ai 的桌面宿主，叠加本地能力：Cowork（隔离 VM 内的本地文件 agent，不上传）、Claude Code 桌面集成 + Remote Control、Computer Use、MCP 连接器 / DXT 扩展 / Skills | Electron + Cowork VM（QEMU/vsock） |
| WorkBuddy | 「AI 原生桌面智能体工作台」：任务式对话、50+ 专家与 10 个专家团队、技能/插件/MCP 三层市场、Automation 定时与工作流、腾讯生态（腾讯文档本地框选即改、乐享知识库、企微/飞书/钉钉遥控、微信聊天记录本地解密） | Electron + 内置 CodeBuddy CLI（Claude Code 同类）+ TuringShield 安全栈 |
| SamePage | 垂直（MCN 带货）资料库 + 问库 + 产物生成的桌面工作台：本地 Obsidian 兼容 vault、投递箱入库 pipeline、Claude Agent SDK 对话、make-ppt/docx 产物、云端私人知识层 | Electron + Agent SDK + PyInstaller pipeline + Supabase |

**结构性差异先说清**：两个参照物都是「通用 agent 壳」，能力来自**生态与执行面**（终端/浏览器/VM/插件市场）；SamePage 的护城河是**入库 pipeline + 实体层 + 图谱 + 垂直提示词**，它们都没有。所以对照表里「它有我无」的很多条不该追，「我有它无」的几条要守。

## 2. 缺口清单与差异化清单（矩阵的两个切面）

**建议做（价值高/中 × 成本小/中，按价值排序）**

1. 需要输入 / 任务完成的系统通知 + Dock 角标（1.7）
2. 对话重命名/置顶/搜索；编辑重发；重新生成；代码块复制；用户消息复制（1.1）
3. 步骤流与正文按时间交织（1.1，动消息模型）
4. 长任务墙钟超时 + before-quit 提示对话在跑（1.3）
5. 单轮用量/档位实际生效角标（1.1）
6. 库级自定义指令 UI（persona 已有格式）（1.4/1.6）
7. 定时入库 / 定时产物（1.10）
8. 窗口尺寸记忆、Cmd+K 命令面板、缩放（1.6）
9. 反向链接/标签浏览（1.4）
10. 建库向导拒绝家目录/磁盘根；外链打开确认；敏感升档确认（1.5）
11. 重置应用数据 / 清缓存重启；诊断 ID（1.6）
12. 深色模式（1.6，刻度表之后）
13. OCR（1.2，成本大但价值高，单独立项）
14. 网关 / key 不落客户端（1.5，成本大，团队版前置）

**明确不做（与垂直定位无关或不可复制）**：内置终端、Computer Use、VM 沙箱、多工作区 Tab、Side Chat、插件市场、BLE/USB、多语言、语音输入、Quick Entry、腾讯文档引擎级 Office 编辑、revert 回退。

**团队版再做**：企业策略下发、企业知识库接入、Remote Control/IM 遥控、跨设备同步、分享任务、MCP 图形化、工作流/hooks、分渠道更新。

**要守住的差异化（我有它无）**：本地 md 库 + 双链 + 图谱 + 实体卡；入库 pipeline（PII 守卫、打标、MOC）；敏感不出网三态；投递箱式自动化；不露供应商名的档位。

## 3. 界面对照（简版）

### 3.1 采集说明与截不到的原因

- 采集工具：`screencapture -x -l <windowID>`，窗口 ID 用 JXA 调 `CGWindowListCopyWindowInfo` 取得。

### 3.3 从两张实截图里能直接学的四条

1. **输入框下沿是「本轮参数」的家**：WorkBuddy 把工作区、权限模式放那里；Claude 把 Accept edits、附件、模型放那里。我们的档位选择器已经在那里（A′ 返工时对齐过），可以把「本轮允许写入」也放进去。
2. **轮内状态行**：Claude 底部一行「耗时 · tokens · 在跑任务数」，成本极低，直接回答了卷二「花了多少/为什么慢」。
3. **步骤行的句法**：「Read 5 files (1 failed), ran 5 commands ›」——动词 + 数量 + 失败数 + 可展开。我们的 `config/steps.ts` 文案可以按这个模板收短。
4. **常驻告警条的用法**：用量接近上限用黄条常驻而不是 toast——与我们 `DESIGN-color-semantics.md`「语义底色只给持续状态」的规则一致，可以直接复用到「本月估算花费超阈值」。
